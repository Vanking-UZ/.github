# Как работаем с кодом

## Ветки
- `main` — то, что работает в проде или готово к сдаче. Напрямую в неё не пушим.
- Новая работа идёт в ветке `тип/кратко`: `feat/order-form`, `fix/bot-timeout`, `chore/deps`.

## Коммиты
Коротко и по делу, в повелительном наклонении: `fix: не дублировать заказ при повторном клике`.
Префиксы: `feat`, `fix`, `refactor`, `docs`, `chore`, `test`.

## Pull Request
1. Один PR — одна задача.
2. Заполни шаблон: что сделано, как проверить, скриншоты для UI.
3. Нужен хотя бы один апрув от коллеги, потом squash-merge.

## Нельзя коммитить
- `.env`, ключи API, токены ботов, пароли. Для примеров есть `.env.example` с пустыми значениями.
- `node_modules`, `venv`, `__pycache__`, сборки, `.DS_Store`.
- Реальные данные клиентов. Для скриншотов и тестов используем выдуманные.

## README проекта
Баннер, одна строка о том, какую задачу решает проект, скриншот, быстрый старт, стек, деплой.
Подпись внизу: `Сделано в vanking.uz`.
